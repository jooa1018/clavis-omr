# ADR-012 — 평가 정렬과 교정 연산 의미

상태: **제안 / Orchestrator 결정 대기** — 2026-09-29. 채택·구현하지 않음.
담당: W4. 기준: EVALUATION v1.0 §4–5, CONTRACTS v0.1 §8·12.5·12.7.

## 중단 근거

00_COMMON §1은 “해석이 결과를 크게 바꾸면 멈추고 에스컬레이션”을 요구한다.
첫 golden 시험의 기대값부터 달라지는 아래 의미를 확정해야 한다.
상류 구현 부재가 블로커는 아니다. 승인 뒤 독립 MusicXML fixture로 구현한다.
헌장과 지시서의 직접 충돌은 확인하지 않았으며, 지표 정의의 공백을 보고한다.

## 결정 요청 1 — K1의 최소화 범위

EVALUATION §4.2는 필드 불일치 수에 비례하는 정렬 비용을 요구하지만 계수를
정하지 않았다. §5.1은 정렬 결과를 typed patch의 “최소 연산 수”로 환산한다.
다음은 **실험 결과나 인식 지표가 아닌**, 정의 판별을 위한 수기 반례다.

- 기준 이벤트와 예측 이벤트의 pitch·duration·tie가 모두 다르다.
  고정된 이벤트 쌍을 필드별 교정하면 세 연산이다.
  이벤트 삭제·삽입으로 쌍을 해체할 수 있으면 두 연산이다.
- note→rest와 duration 오류가 함께 있다. replace-event가 완성 이벤트를
  교체한다면 한 연산으로 둘 다 해결되지만, 오류 필드별 합산은 중복 과금한다.
- 삭제·삽입 비용에 맞춰 정렬하면 같은 오류가 pitch 불일치 또는 누락으로
  보고될 수 있다. K1뿐 아니라 필드 정확도와 pairs.json도 달라진다.

선택 A: 정렬을 고정하고 필드별 비용을 더한다. 구현은 간단하지만 전역 최소
교정 부담이라는 해석과 다르다. 최소화가 정렬된 쌍 내부임을 명시해야 한다.

선택 B (**권고**): 이벤트 정렬의 비용 자체를 허용 교정 연산 수로 삼는다.
누락·여분은 각각 한 연산, 같은 kind의 치환은 pitch·duration·tie 그룹별 합,
다른 kind는 완성 이벤트 replace-event 한 연산으로 처리한다.
같은 kind에서 임의 replace-event를 허용하지 않는지 함께 명시해야 한다.
이는 전체 악보의 전역 최적화를 주장하지 않고, §4.2의 계층적 정렬 안에서
이벤트열 편집 비용을 최소화하는 정의다. 둘 중 어느 의미인지 승인 필요.

## 결정 요청 2 — onset만 다른 이벤트

`forward` 등으로 onset만 바뀌고 pitch·duration·kind·tie는 같은 쌍이 가능하다.
§5.2는 onset을 편곡 영향 오류에 포함하지만 §5.1 K1 표에는 onset 행이 없고,
CONTRACTS §12.7에는 onset 전용 patch가 없다.

선택 A: K1에는 더하지 않고 onset 불일치를 pairs와 measureExact에 기록한다.
선택 B (**권고**): 공개 patch로 가능한 교정(삭제·삽입 또는 replace-event)을
정확히 지정하고 그 비용을 K1에 반영한다. 어떤 연산인지 Orchestrator 결정이
필요하며, patch 어휘·의미를 바꾸게 되면 W1과 CCR 절차를 먼저 거친다.
평가기에서 임의 `onset` patch를 발명하거나 계약을 직접 고치지 않는다.

## 결정 요청 3 — 정확도 분모와 measureExact 범위

§5.4는 “해당 필드”의 기준 요소를 분모로 한다. pitch가 없는 rest/rhythm을
pitchExact 분모에 넣는지, 가사 오류가 measureExact를 낮추는지 명시되지 않았다.

권고안:

- pitchExact: 기준 pitched note만 분모. 누락 또는 non-note 대응은 오답.
- durationExact: 평가 대상 기준 이벤트 전체. grace 포함 여부는 투영 정의에
  명시하고, grace의 부재 duration을 임의의 기보 음가로 추정하지 않는다.
- measureExact: 1:1 대응 마디의 모든 평가 투영 필드가 일치해야 한다.
  이벤트의 onset·pitch·duration·kind·tie, 속성, 코드 값·위치, 가사 부착·텍스트,
  진행 요소 및 누락·여분을 포함한다. 분할·병합은 exact가 아니다.
- 의미 없는 ID·표시 마디 번호·성부 이름 재번호·divisions 직렬화는 제외한다.
- 분모가 없으면 null과 denominator=0을 보고하고, 완벽 점수로 채우지 않는다.
- 첫 PR에서 지원하지 않는 투영 요소는 조용히 버리지 않고 평가 불가로 표시한다.

위 범위를 채택하거나, 가사를 제외할 경우 명시적 대안을 요청한다.

## 승인 후 정렬 구현안

추가 모델·인식 규칙 없이 Fraction 기반 투영과 결정적 DP를 쓴다.
마디 DP는 이벤트 튜플 다중집합의 대칭차 크기를 내용 비용으로 삼고,
삽입·삭제는 해당 마디 이벤트 수, 분할·병합은 내용 비용에 barline 한 연산을
더하는 안을 제안한다. 빈 마디 삽입·삭제에도 구조 비용이 필요하므로 최소 한
연산으로 둔다. 최종 비용표는 위 K1 결정과 함께 승인받아 configs/eval에 고정한다.
분할·병합 비교에서는 이어 붙인 마디의 onset을 누적 길이로 이동한다.
이벤트 DP 동점은 대응→삭제→삽입, 마디 DP 동점은 1:1→분할→병합→삭제→삽입,
동일 후보는 입력 문서 순서로 결정한다. 실제 성부 번호를 점수 특성으로 쓰지 않는다.
다성부 최적 매칭은 후속 범위이며 첫 PR은 단일 보표·단일 성부만 지원한다.
모든 쌍과 원본 위치, 필드별 오류, 연산 내역을 pairs.json에 남긴다.

## 첫 golden 10쌍 계획 (아직 fixture·시험 아님)

| 쌍 | 독립 수기 MusicXML의 차이 | 검증 대상 |
|---|---|---|
| 01 | 완전 동일 | 자기 비교 |
| 02 | divisions만 변경 | Fraction 동등성 |
| 03 | 성부 번호만 변경 | 의미 없는 재번호 |
| 04 | pitch만 변경 | pitch 오류 |
| 05 | duration만 변경 | duration 오류 |
| 06 | 이벤트 하나 누락 | 누락 포함 분모 |
| 07 | 이벤트 하나 여분 | 여분 교정·measureExact |
| 08 | note↔rest와 duration 동시 변경 | replace-event 중복 과금 방지 |
| 09 | 같은 harmony 의미, kind@text는 M7/maj7 | 코드 인쇄형 동등성 |
| 10 | 가사 음절 또는 부착 변경 | 가사 투영·measureExact 범위 |

onset 단독과 pitch·duration·tie 복합 반례, 빈 분모는 추가 경계 시험으로 둔다.
승인 전 기대 지표 JSON이나 통과 결과를 만들지 않는다.

## 근거와 되돌릴 조건

실사·합성 데이터 측정 없음. 위 근거는 명세의 연산 표와 수기 반례뿐이다.
데이터에 맞춰 비용을 튜닝하지 않는다. 승인 기록은 이 문서에 추가한다.
돌연변이 시험에서 허용 교정 연산 수와 불일치하면 회귀로 보고하고 재검토한다.
이미 공개된 평가기 정의를 바꾸면 버전을 올리고 main·기준선을 재측정한다.
계약 변경이 선택되면 별도 CCR 승인 전에는 그 변경에 의존하는 구현을 진행하지 않는다.
