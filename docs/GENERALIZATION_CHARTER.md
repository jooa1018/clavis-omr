# Clavis 일반화 헌장 (Generalization Charter) v1.0

> 이 헌장은 모든 워커에게 적용된다. 이 헌장과 지시서가 충돌하면 헌장이 우선한다.
> 목적은 하나다. **"우리가 가진 몇 장의 악보에서 잘 되는 엔진"이 아니라 "처음 보는 실사용 저해상도 악보에서 잘 되는 엔진"을 만든다.**

## 1. 왜 필요한가

HarmonyMaker의 이전 OMR 작업은 실패한 한 장의 JPEG를 반복해서 들여다보며 설정과 규칙을 고쳤다. 그 결과 개발 입력의 수치는 좋아졌지만 처음 보는 악보에서의 성능은 증명되지 않았다(PLAN.md 1절). 이런 개선은 대부분 착시다. 이 헌장은 그런 착시를 **구조적으로 불가능하게** 만든다.

## 2. 금지 행위

아래 행위는 의도와 상관없이 금지한다. 발견되면 PR을 거절하고 이미 병합됐으면 되돌린다.

| ID | 금지 행위 | 예시 |
|---|---|---|
| F1 | **입력 식별 정보로 분기** | 파일명, 해시, 제목·작곡가 문자열, EXIF 기기명, 페이지 픽셀 크기, 페이지 수, 곡 길이 등으로 동작을 바꾸는 코드 |
| F2 | **개별 이미지에 맞춘 상수** | 한두 장에서 잘 되도록 정한 임계값, 계수, 커널 크기. 출처 기록 없는 매직 넘버 |
| F3 | **정답 조회·주입** | 기대 출력(코드 목록, 음표 배열, 마디 수)을 코드·설정·모델 입력에 넣는 것. 런타임이 평가 정답 파일을 여는 것 |
| F4 | **위치 특화 규칙** | "38마디는 슬래시로 처리", "마지막 시스템은 2성부"처럼 특정 마디, 시스템, 페이지 번호를 가정하는 규칙 |
| F5 | **Sealed 접근** | sealed 이미지나 정답을 보거나 요청하거나 추정하는 것, sealed 결과를 역추적하는 실험 |
| F6 | **평가기 조작** | 수치를 좋게 보이려고 정렬 비용, 지표 정의, 제외 목록을 바꾸는 것. 평가기는 W4만 버전을 올려 바꾸며, 바꾸면 기준선부터 전부 다시 측정한다 |
| F7 | **평가 영역 선별** | 잘 나오는 페이지나 슬라이스만 보고하거나 실패 페이지를 조용히 빼는 것 |
| F8 | **학습 데이터 오염** | Dev, sealed, R-LIED, R-TGT 이미지나 그 곡을 학습에 넣는 것. 이미지 일부(배경, 텍스처)를 잘라 쓰는 것도 포함 |
| F9 | **근거 없는 생성** | 마디 길이나 문법을 맞추려고 보이지 않는 음표, 쉼표, 붙임줄, 가사, 코드를 만드는 것 |
| F10 | **검사 우회** | 유효성 검사, 결정성 검사, 스캐너 규칙을 끄거나 예외 목록에 몰래 추가하는 것 |
| F11 | **체크포인트 쇼핑** | Dev-Check나 sealed 점수를 보고 여러 체크포인트나 시드 중 가장 좋은 것을 고르는 것. 선택은 사전에 정한 기준(SYN-Val, Dev-Tune)으로만 한다 |
| F12 | **출판사·양식 특화 수작업 규칙** | "이 출판사 악보는 코드가 굵으니 X" 같은 규칙. 양식 차이는 데이터 다양화와 학습으로 흡수한다 |

### 금지 코드의 전형

```python
# F1: 식별 정보 분기 — 금지
if page_sha256 == "8858cee03d27...":
    ...
if page.width == 1170 and page.height == 2532:   # 특정 기기 해상도
    ...
# F2: 한 장에서 맞춘 상수 — 금지
BEAM_MIN_THICKNESS = 0.4137          # 출처 없는 값
# F3: 정답 조회 — 금지
EXPECTED_MEASURES = 39
# F4: 위치 특화 — 금지
if measure_index >= 38:
    treat_as_slash(...)
```

| A5 | 분포 수준 적응 | Dev-Tune **집계 통계**(interline 분포, 흐림 정도, 압축 강도, 흔한 양식 특징)로 생성기와 열화기 분포를 넓히는 것. 개별 이미지를 모사하지 않는다 |
| A6 | 일반 속성 기반 분기 | interline, 흐림, 신뢰도처럼 **측정 가능한 일반 속성**에 기반한 분기. 임계값은 A2나 A3 절차를 따른다 |

## 4. 상수와 임계값 관리

`src/clavis`에서 쓰는 기하·판정 상수는 모두 `configs/<module>/constants.yaml` 레지스트리에 둔다. 코드에는 숫자 리터럴 대신 레지스트리 키를 쓴다. 0, 1, 2 같은 자명한 값과 단위 변환은 예외다.

```yaml
- name: geometry.barline.min_height_ratio
  value: 0.85
  unit: staff_height            # staff_space | staff_height | px_at_s_star | ratio | probability
  owner: W5
  source: fit                   # convention | fit | model
  rationale: "barline 후보가 보표 높이의 85% 이상을 덮어야 한다"
  fitted_on: "dev-tune@sha256:…"   # source=fit일 때 필수
  metric: "barline F1 (R-Dev-Tune, SYN-Val)"
  evidence: "docs/reports/W5/sweeps/barline_min_height.json"
  updated: 2026-10-14
```

- 단위는 **staff-space 계열이나 무차원**이어야 한다. 원본 픽셀 단위 상수는 금지다(해상도 불변성).
- `source: fit` 값을 바꾸려면 sweep 결과와 전후 Dev 보고서가 있어야 한다.

## 4.2 규칙 카탈로그 (PLAN v1.1의 핵심 장치)

GPU 없는 검출–분류–조립 구조는 손으로 쓴 규칙이 늘기 쉽다. 규칙이 늘어나는 곳이 곧 하드코딩이 스며드는 곳이다. 그래서 **모든 조립·판정 규칙**(W5 기하, W6 관계·읽기 구성, W8 조립·구조)을 `configs/<module>/rules.yaml`에 등록한다.

```yaml
- id: SYM-REL-003
  owner: W6
  statement: "위로 향한 stem은 음표 머리의 오른쪽 가장자리에 붙는다(표준 조판 관례)"
  units: staff_space
  params: [symbols.relation.stem_head_dx_max]
  source: convention            # convention | fit
  flag: symbols.rules.SYM-REL-003.enabled
  ablation:                      # 게이트마다 갱신
    dev_tune_k1_delta: -0.42     # 규칙을 끄면 K1이 얼마나 나빠지는가(음수 = 규칙이 도움)
    syn_val_ier_delta: -0.8
    report: docs/reports/W6/ablation/G1.json
  introduced_by: "PR #…"
  motivated_by_failure: false    # true면 5.3절 실패 패턴 패키지 경로 필수
```

- 규칙은 **조판 관례나 음악 이론의 일반 문장**으로 설명할 수 있어야 한다. "이 악보에서는 …"으로 시작하는 설명은 규칙이 아니다.
- 모든 규칙은 설정 플래그로 끌 수 있어야 한다. nightly ablation이 규칙별 기여도를 잰다(6절).
- 게이트마다 규칙 수와 기여도 표를 보고한다. **기여가 0 이하인 규칙은 제거 후보**다. 규칙 수가 늘었는데 지표가 제자리면 오케스트레이터가 해당 모듈을 검토한다.

## 5. 변경 승인 기준 — 인식 결과에 영향을 주는 모든 PR

1. **전체 평가를 실행한다.** R-Dev 전체(Dev-Tune + Dev-Check)와 SYN-Val-quick을 돌리고, 이전 main과 page 단위 paired bootstrap으로 비교한 보고서를 첨부한다. SYN-Val-nightly는 매일 밤, SYN-Val 전체는 게이트에서 돈다(EVALUATION.md 7.1절). 일부 페이지만 골라 돌린 결과는 근거로 인정하지 않는다.
2. **슬라이스 회귀가 없어야 한다.** 사전에 정한 슬라이스(EVALUATION.md 5.11절: tier, interline 구간, 촬영 경로, 조판 도구, 기보 특성) 가운데 어느 곳에서도 유의한 악화가 없어야 한다. 악화가 있으면 이유와 대가를 명시하고 오케스트레이터 승인을 받는다.
3. **실패 패턴 일반화를 증명한다.** 특정 실패 사례를 보고 시작한 변경이라면 다음을 제출한다.
   - (a) 실패를 **일반 용어로 기술한 패턴** (예: "오선과 겹친 2중 beam이 저해상도에서 1중으로 보인다")
   - (b) 그 패턴의 **합성 사례 계열 ≥ 20개**: 다른 곡, 폰트, 해상도, 열화 조합으로 LeadGen·W3를 써서 만든다. 여기에 Dev 안의 같은 패턴 사례 목록을 더한다
   - (c) 계열 전체에서의 개선과, SYN-Val·R-Dev 전체에서 회귀가 없음을 보여 준다
   - (d) 원래 실패 이미지 **하나만** 좋아진 변경은 기각한다
4. **규칙은 카탈로그에 등록하고 끌 수 있어야 한다.** 규칙 기반 구성요소는 4.2절 카탈로그에 등록하고, 설정 플래그로 켜고 끌 수 있어야 하며, 켰을 때와 껐을 때의 기여도(ablation) 보고가 있어야 한다.

## 7. 데이터 격리

- **Sealed (OR-003)**: Custodian만 보관하고 실행한다. 후보의 해시·선율 지문을 로컬에서 동결 학습 inventory와 Dev inventory에 대조해 충돌 후보를 제외한다. 밖으로는 후보·제외 건수와 허용된 평가 집계만 보낸다. sealed 선율 지문은 누구에게도 넘기지 않는다(4음 조각 역산 가능). 학습 데이터를 sealed 결과로 다시 거르지 않는다. R-PC sealed 곡은 보호된 평가 전용 곡 풀에서 선택한다.
- **보호 집합 갱신 (OR-003)**: Dev 접수마다 버전을 올리고 다음 학습 전에 재필터한다. 새 충돌 곡은 다음 학습부터 빼되 기존 체크포인트를 소급 재학습하지 않는다. 그 곡의 Dev 페이지는 평가 보고에서 오염 슬라이스로 분리한다. 새 충돌 곡 비율이 학습 곡의 1%를 넘으면 Orchestrator에게 보고한다.
- **측정 전용 학습 (OR-003)**: 편입 전 LeadGen 개발 프로필 출력·smoke 렌더만 속도 측정·경로 시험에 쓸 수 있다. eval-* 시드, PDMX 곡, 실사 이미지는 제외한다. 체크포인트는 measurement-only로 표시하며 평가 보고·엔진 모델·체크포인트 선택에 사용하지 않는다.
- **평가 전용 곡 풀(eval-reserved pool)**: R-PC용 곡은 이 풀에서만 뽑는다. 풀의 멜로디 지문은 학습 데이터 필터에 등록돼 학습에 들어가지 않는다.
- **R-LIED**(OpenScore Lieder): 코퍼스 전체를 학습에서 제외한다.
- **R-TGT**(사용자 찬양 악보): 평가 전용이다. 저장소, CI, 클라우드 환경에 두지 않는다.
- **R-LEGACY**: 이미 개발에 쓰인 이미지다. Dev 회귀 사례로만 쓰고 "일반화 증거"로 인용하지 않는다.
- Dev는 **Dev-Tune**(임계값·보정 적합용)과 **Dev-Check**(확인용)로 나눈다. Dev-Check로 무엇을 적합하면 그 순간 Dev-Check는 Dev-Tune으로 강등된다.

## 8. PR 리뷰 체크리스트 (PR 템플릿에 포함)

- [ ] 입력 식별 정보(파일명, 해시, 크기, 제목, 인덱스)로 분기하는 코드가 없다
- [ ] 새 상수는 레지스트리에 단위, 출처, 근거와 함께 등록했다
- [ ] 인식에 영향이 있으면 R-Dev 전체와 SYN-Val 비교 보고서를 첨부했다(paired bootstrap)
- [ ] 특정 실패에서 시작했다면 실패 패턴 일반화 패키지(5.3절)를 첨부했다
- [ ] 규칙 기반 변경은 규칙 카탈로그 항목, 플래그, ablation이 있다
- [ ] 이 변경이 스케일 0.8배나 1.25배, 회전 1°, 처음 보는 곡에서도 같은 방식으로 작동한다고 설명할 수 있다
- [ ] 평가기, 정답, sealed, Dev 이미지 목록을 런타임이 참조하지 않는다
- [ ] 보고서는 dev/sealed, 합성/실사, 자동/수동을 구분했고 실패 슬라이스를 포함했다

## 9. 위반 시 처리

1. 해당 변경을 되돌린다.
2. 원인 보고서를 `docs/reports/incidents/`에 남긴다.
3. 영향받은 지표를 다시 측정한다(기준선 포함).
4. sealed 노출이 의심되면 해당 sealed 세트를 **소각**(Dev로 이관)하고 Custodian이 새 sealed를 만든다. 소각한 세트의 결과는 이후 일반화 근거로 쓰지 않는다.
