# omr_DEV후보 11쪽: 부분 전사 안내

11쪽의 원본을 그대로 보존하고 쪽마다 무작위 2–4개 시스템만 전사합니다.
목표는 읽을 수 있는 사실을 기록하는 것입니다. 판독 불가 음이나 쉼표를 추측해
채우지 않습니다. 약 15–30분/쪽 전사(총 3–5.5시간)와 다른 날 검토가 필요하므로,
준비된 페이지부터 나누어 전달해도 됩니다. 이 시간은 계획 추정이며 측정값이 아닙니다.

## 1. 비공개 위치 지정 (약 10분)

예시 폴더는 `C:\Users\eccto\ClavisPrivate`입니다. Git 저장소나 자동 클라우드
동기화 폴더 안에 만들지 않습니다. 이미 밖에 있는 omr_DEV후보는 원본을 보존하고
복사본을 아래 `dev` 구조에 정리하면 됩니다. 보류/봉인 자료는 이 폴더에 넣지 않습니다.

PowerShell에서 다음처럼 지정합니다. 경로는 실제로 만든 로컬 폴더로 바꾸세요.

```powershell
$env:CLAVIS_PRIVATE_ROOT = 'C:\Users\eccto\ClavisPrivate'
```

이 설정은 현재 PowerShell 창에만 적용됩니다. 창을 새로 열면 다시 지정합니다.
영구 설정을 원하면 Windows ‘사용자 환경 변수’에 같은 이름과 경로를 등록합니다.
저장소의 `.env`나 설정 파일에 사적 경로를 넣지 않습니다.

```text
ClavisPrivate/
  dev/dev-001/original.jpg
  dev/dev-001/selection.json
  dev/dev-001/source.mscz
  dev/dev-001/partial.musicxml
  dev/dev-001/render.pdf
  dev/dev-001/intake.txt
  dev/dev-001/measure-map.csv
```

같은 방식으로 dev-002 … dev-011을 사용합니다. PDF 원본이면 original.pdf를 보존하고
원본 PDF의 페이지 번호를 intake.txt에 적습니다. 사진을 보정하거나 다시 압축한 것을
원본으로 바꾸지 않습니다. 잘림·회전본은 별도 파일로 남깁니다.

## 2. 먼저 무작위 시스템 선택 기록 (약 2분/쪽)

‘시스템’은 위에서부터 한 줄씩 함께 읽는 보표 묶음입니다. 2단 보표가 함께 연주되면
한 시스템입니다. 쪽의 총 시스템 수만 세고 전사하기 전에 개수와 seed를 고정합니다.
기본 3개, 총 시스템이 2개면 2개, 여유가 있으면 사전에 4개로 정합니다.
한 시스템뿐인 페이지는 전체를 전사하고 intake.txt에 `whole-page`라고 적습니다.

W4 worktree의 PowerShell에서 다음을 실행합니다(6은 해당 쪽의 총 시스템 수로 변경).

```powershell
.venv\Scripts\python.exe -m eval.gt select --page-id dev-001 --systems 6 --count 3 --seed dev-intake-session1 --date 2026-09-29 --out dev/dev-001/selection.json
```

날짜는 실제 선택한 날짜로 바꿉니다. seed는 이 작업 묶음에서 미리 고른 문자열을
모든 쪽에 유지해도 됩니다. 생성된 `selectedSystems` 번호만 전사합니다.
쉽거나 선명한 시스템이 나오도록 재추첨하지 않습니다. 기존 기록은 도구가 덮어쓰지
않습니다. 잘못 센 경우 원래 기록과 이유를 보존하고 W4에 알려 주세요.
명령 실행이 어렵다면 페이지별 총 시스템 수만 먼저 알려 주시면 W4가 선택 기록을
만들겠습니다. 선택이 끝나기 전에는 임의로 읽기 쉬운 부분부터 고르지 않습니다.

## 3. MuseScore 부분 전사 (15–30분/쪽)

1. 새 악보를 로컬에 만들고 원본의 주선율 보표·음자리표·박자·조표를 설정합니다.
   선택한 시스템을 위에서 아래 순서로 입력합니다. 두 성부가 실제로 있으면 두 성부를
   유지하고, 보이지 않는 반주나 화음을 추가하지 않습니다.
2. 음높이·길이·임시표·점·쉼표·붙임줄, 코드 값과 붙은 위치, 가사와 절 배정을 그대로
   입력합니다. 도돌이·볼타가 선택 영역에 있으면 기록합니다. 재생이 자연스럽도록
   음을 고치지 않습니다.
3. 건너뛴 시스템은 전사하지 않고 빈 마디나 쉼표로 채우지 않습니다. 선택 영역이
   이어지지 않으면 줄바꿈으로 구분하고 `measure-map.csv`에 원본 위치를 기록합니다.
   새 영역의 지속 조표·박자·음자리표는 앞 원본을 확인해 입력합니다. 경계의 tie나
   문맥을 확인할 수 없으면 ‘문맥 불명’으로 남기고 추측하지 않습니다.
4. 자동으로 생긴 쉼표·보이지 않는 쉼표가 원본에 실제 있는지 확인합니다. 못갖춘마디를
   정규 마디 길이로 억지로 채우지 않습니다. 앱 사용법이 어려운 부분은 수정 전 상태를
   저장하고 해당 마디를 intake.txt에 적어 W4에게 알려 주세요.
5. `source.mscz`를 로컬 저장하고 **파일 → 내보내기**에서 압축하지 않은 MusicXML
   (`partial.musicxml`)과 PDF(`render.pdf`)를 내보냅니다. MuseScore 4는 MusicXML 4.0을
   사용합니다. [공식 내보내기 안내](https://handbook.musescore.org/file-management/file-export)

입력 모드 `N`, 길이 선택 후 음이름 A–G, 쉼표 `0`으로 입력할 수 있습니다.
[공식 음표·쉼표 입력 안내](https://handbook.musescore.org/basics/entering-notes-and-rests)

`measure-map.csv` 예(숫자는 예시이며 자신의 원본 위치를 적습니다):

```csv
sourceSystem,sourceMeasureLabel,xmlMeasurePosition
2,5,1
2,6,2
4,13,3
4,14,4
```

원본에 마디 번호가 없으면 `시스템2-첫마디`처럼 위치로 적습니다. XML 위치는 현재
부분 전사의 첫 마디부터 1,2,3…입니다. W4가 이 표를 evalRegions의 마디 범위·원본
좌표에 연결합니다. JSON 좌표나 SHA256을 직접 작성할 필요는 없습니다.

## 4. 렌더 대조와 다른 날 재검토

원본과 render.pdf를 나란히 놓고 선택한 모든 마디를 대조합니다. 각 음의 높이·길이,
쉼표·tie·임시표·코드·가사·마디선을 확인하고, 수정하면 MusicXML/PDF를 다시 내보냅니다.
듣기만 해서는 음이름·tie·코드 위치의 정답을 확인할 수 없습니다.

다른 날 같은 대조를 한 번 더 합니다(계획상 5–10분/쪽). 가능하면 다른 사람이 검토하고,
혼자 확인했다면 그대로 기록합니다. 실제 검토한 날짜만 적습니다.
Dev 전사에 엔진 결과를 초안으로 썼으면 `assisted: true`와 사용 사실을 적고 모든 선택
마디를 확인합니다. 원문 판독이 안 되는 위치는 시스템·마디·대략 위치를 남깁니다.

준비되면 이 대화에 **CLAVIS_PRIVATE_ROOT 경로, 준비된 페이지 ID, 남은 검토 항목**만
알려 주세요. 파일을 채팅이나 GitHub에 업로드하지 않습니다. W4가 해당 Dev 폴더만
접수해 `gt.json`, 해시, manifest, 곡 단위 Dev-Tune/Check 분할을 완성하겠습니다.
11쪽만으로 G0의 Dev 20쪽·범주 균형 목표가 충족되지는 않습니다. 범위 부족과 미상
항목은 보고서에 남기고 추가 R-PC·R-LEGACY·R-LIED 자료와 함께 확인합니다.
