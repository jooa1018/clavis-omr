# CCR-0003 — T1.4 LSTL 열 문맥과 정규 텍스트 보완

상태: 초안 / Orchestrator 판정 대기 · 작성: W1 · 2026-10-09

## 1. 동기와 근거
CONTRACTS 4.2는 같은 열의 성부/화음 순서를, 4.4는 chord=1의 같은 열 조건을 요구한다.
그러나 LSTLItem에는 열 정보가 없고 StaffLattice의 LatticeItem에는 spanU만 있다.
spanU는 인쇄 박스 범위이며 같은 음악 시점을 공유하는 열의 식별자가 아니다.
열 추정을 W1에서 구현하면 W6 인식 범위와 겹치므로 하지 않는다.

같은 토큰 두 개라도 아래 열 정보에 따라 판정이 달라진다.

```text
note dur=quarter pos=0 head=normal v=1
note dur=quarter pos=2 head=normal v=1 chord=1
```

columnIndex=[0,0]이면 같은 열 화음 후보지만 [0,1]이면 두 번째 chord=1은 무효다.
텍스트만으로 어느 경우인지 결정할 수 없다.
W1 지시서 6절의 "계약의 모호함을 코드로 조용히 결정하지 않는다. 모호하면 CCR 초안을 써서 Orchestrator에게 묻는다."에 따라 요청한다.

## 2. 결정 요청

### C1. 열 정보 전달
**권장안: 기존 IR은 유지하고, 정규화기/시퀀스 검증기에 호출자가 명시적 열 문맥을 별도 전달한다.**
각 토큰에 대응하는 columnIndex와 각 열의 인쇄 x 범위를 받는다.
같은 열은 같은 index를 쓰며 비시간 항목은 자기 열을 갖는다. index는 정규화 결과에서 0부터 연속한다.
W2는 렌더 정답에서, W6는 읽기 구성에서 열을 제공한다. W1은 간격 임계값이나 박스 겹침으로 음악 시점을 추정하지 않는다.
W8/W4는 동일한 열 문맥을 전달할 때만 전체 시퀀스 검증을 수행한다.
열이 없으면 항목/텍스트 검증만 가능하며, 전체 문법 검증 API는 COLUMN_CONTEXT_REQUIRED 오류를 반환한다.
allowed(state), advance(state,item)는 명시적 현재 열 문맥을 포함한 상태를 사용한다.

대안: LatticeItem에 columnIndex를 추가해 문맥을 IR에 영속화한다.
이 경우 CONTRACTS 0절의 patch 변경과 fixture/schema/소비자 마이그레이션이 필요하다.
권장안의 한계는 StaffLattice/텍스트만 저장했다가 다시 읽는 소비자가 열 문맥도 별도로 보존해야 한다는 점이다.
어느 전달 방식을 채택할지 Orchestrator 판정이 필요하다.

### C2. 정규 텍스트와 기본값
권장안은 ending을 `ending numbers=[1,2] mark=start`처럼 공백 없는 JSON 정수 목록으로 쓴다.
속성은 4.1절 순서, 항목당 한 줄, UTF-8/NFC/LF, 출력은 마지막 LF 하나로 고정한다.
선택 속성의 none/false/0은 기존 규칙대로 생략한다. dots=0은 4.3 예시대로 생략하고 파싱 시 복원한다.
기본값이 정의되지 않은 필수 값(pos=0, fifths=0 등)은 생략하지 않는다.
선택 rest.pos=0도 값이 있는 위치와 위치 미제공을 구분하기 위해 보존한다.
알 수 없는/중복 속성, 잘못된 순서·기본값을 명시한 비정규 표기는 strict parser가 거부한다.
토큰 텍스트 자체에는 열 경계를 추가하지 않으며 C1의 별도 문맥을 사용한다(권장안 채택 시).

### C3. 인쇄 순서 제약 충돌
겹치지 않는 열은 왼쪽부터, 겹치는 열은 계약에 명시된 조판 우선순위를 적용한다.
이 선행 관계가 순환하거나 계약만으로 유일한 정규 순서를 정할 수 없으면
AMBIGUOUS_COLUMN_ORDER로 거부하고 호출자가 문맥을 보완한다. 임계값이나 임의 음악 순서를 만들지 않는다.
예: 초기 time=[0,3], key=[2,5], clef=[4,7]은 겹침 우선순위와 disjoint x 순서가 순환할 수 있다.
이 수치는 합성 구간 반례이며 인식 상수나 실제 악보에서 얻은 값이 아니다.

## 3. 버전과 마이그레이션
권장 C1은 기존 IR JSON/Schema/fixture와 LSTL 어휘 값을 바꾸지 않는다.
C2/C3를 기존 lstl-0.1 명세의 명확화로 볼지, 0절에 따른 lstl-0.1.1 보완으로 볼지도 판정 요청한다.
W1이 v0.1 동결 예외를 임의 적용하지 않는다. IR 필드 대안을 채택하면 patch 마이그레이션 계획을 먼저 확정한다.

## 4. 영향 모듈과 평가
W2 라벨, W6 읽기 구성, W8 입력 검증, W4 평가용 문법 검증, W1 공통 패키지가 대상이다.
인식 결과나 평가기 지표를 변경하지 않는다. 사적/Dev/sealed 접근은 필요 없다.
승인 뒤 golden 20개 이상 왕복, 무효 사례 30개 이상, 같은/다른 열·성부·화음·courtesy·겹침 반례를 합성으로 시험한다.
텍스트 왕복과 열 문맥을 포함한 전체 문법 검증의 결과를 구분해서 보고한다.

## 5. 적용 상태
초안만 작성했다. CONTRACTS.md, 모델, Schema, 어휘, 파서, 오토마톤은 변경하지 않았다.
COMMON 8절 및 W1 지시서 6절에 따라 판정 전에는 위 선택에 의존하는 T1.4 구현을 진행하지 않는다.
