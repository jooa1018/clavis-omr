## 1. 미션

악보 위의 **글자**를 읽는다. HarmonyMaker에게 코드 심벌은 편곡의 뼈대이고, 가사는 재발음 여부를 결정한다. 저해상도에서 작게 찍힌 코드(위첨자 확장음, ♭·♯ 기호, 재즈풍 손글씨체)와 음표 간격에 맞춰 흩어진 한글 음절을 안정적으로 읽어야 한다. 코드는 **문법을 통과한 것만** 낸다.

**GPU를 쓰지 않는다.** 텍스트 검출과 가사 인식은 PP-OCRv5 사전학습 모델(Apache-2.0)을 **학습 없이** 쓴다. 성능은 모델 재학습이 아니라 입력 준비(악보용 음절 덩어리 분할, 적절한 crop과 크기 조정)와 후처리(문법, 정렬)로 끌어올린다. 직접 학습하는 것은 작은 분류기와, 비교에서 이길 때만 쓰는 소형 코드 인식기뿐이며 둘 다 CPU에서 4시간 안에 학습된다.

## 2. 범위

- 범위: 텍스트 줄 검출, 역할 분류, 코드 인식(문법 제약), 가사 OCR(한국어·영어)과 음절 분리, 절 배정, 제목·템포·섹션·진행 문구·리허설 마크 해석, `TextIR` 출력
- 범위 밖: 코드와 가사를 음표 시점에 부착하는 일(W8). 너는 위치(박스)와 보표 연결을 정확히 넘긴다.

## 3. 작업 목록

### T7.1 텍스트 검출 (ADR-005)

- PP-OCR 검출 모델(DBNet 계열, Apache-2.0)을 ONNX로 **학습 없이** 쓴다. 입력은 processed 페이지와 W5 비오선 마스크다.
- SYN 텍스트 박스와 R-PC 정합 GT로 재현율을 잰다. 작은 코드 글자나 저해상도에서 부족하면 먼저 입력 쪽을 고친다: 보표 위·아래 탐색 띠만 잘라 확대해 넣기, 여러 배율로 검출해 합치기. 재학습은 하지 않는다.
- 출력은 텍스트 줄 박스(processed 좌표)와 가장 가까운 보표 연결(위·아래, staff-space 거리)이다.

### T7.2 역할 분류

- 역할: chord, lyric(n절), title, subtitle, tempo, section, navigation, rehearsal, credit, pageNumber, other
- 특징: 보표 대비 상대 위치(staff-space), 시스템을 가로지르는 줄 정렬, **음표 머리 열(W6 `SymbolGraph`)과의 x 정렬**, 글자 통계(한글 비율, 숫자, 코드 문법 통과 여부), interline 대비 글자 크기, 페이지 위치, 테두리 상자(리허설 마크), 시스템마다 반복되는 패턴
- 모델: LightGBM(CPU, 수 분 학습). SYN으로 학습하고 R-Dev-Tune으로 검증한다.
- 혼동이 잦은 쌍(리허설 문자 "A" ↔ 코드 "A", 셋잇단 "3" ↔ 숫자, 볼타 번호 ↔ 코드)은 문맥 특징으로 구분하고, 혼동 행렬을 매 보고서에 싣는다.

### T7.3 코드 인식기 (ADR-015)

두 구성을 만들고 SYN-Val과 R-Dev-Tune에서 비교해 채택한다.

- **구성 A (학습 없음)**: PP-OCR 라틴 인식 모델의 문자별 CTC 확률을 그대로 받아, 코드 문법 오토마톤으로 제한한 CTC beam search를 직접 돌린다. 인식 모델의 사전에 없는 글리프(♭, ♯, △, ø, ° 등)는 혼동되는 문자(b, #, A, o 등)와의 대응표로 처리한다. 대응표는 일반 표기 관례이며 레지스트리에 둔다.
- **구성 B (CPU 학습)**:
  - 합성 코드 crop 생성기: CONTRACTS.md 6절 문법에서 코드를 샘플하고 인쇄 변형을 입힌다. 변형에는 `M7`/`maj7`/`△7`/`Δ7`, `-7`, `ø`, `°`, 위첨자 확장음, 괄호 변화음, 슬래시 베이스, ♭·♯ 글리프와 b·# 문자, 굵기, 기울임, 재즈 손글씨풍 폰트가 들어간다. W3의 텍스트용 열화(저해상도 포함)를 적용한다.
  - 모델: 소형 CRNN-CTC(≤ 100만 파라미터, 높이 32 px 입력). 문자 집합은 코드 표기 전체(글리프 포함)다. W1 배치 실행기로 **CPU 4시간 안에** 학습한다.
- 두 구성 모두 **문법 제약 디코딩**을 거쳐 문법을 통과하는 문자열만 낸다. 출력은 정규형, 인쇄형(`kindText`), 대안(확률)이다.
- HarmonyMaker 어휘 적합성 fixture(CONTRACTS.md 12.6절의 모든 표기)를 테스트로 둔다. 어휘 밖 코드는 정확히 내고 W8이 힌트를 달 수 있게 표시한다.

### T7.4 가사 OCR (ADR-016)

- `korean_PP-OCRv5_mobile_rec`(한국어)와 라틴 문자 인식 모델(Apache-2.0)을 ONNX로 **학습 없이** 쓴다. 라이선스를 등록부에 확인해 올린다.
- **악보 가사의 특성**: 음절이 음표 간격에 맞춰 넓게 흩어지고, 하이픈과 연장선이 끼어 있다. 줄 전체를 일반 문장처럼 읽으면 실패하기 쉽다. 따라서 가사 줄을 **음절 덩어리**(가로 간격 기준, staff-space 단위)로 나눠 인식하고, 짧은 가로 대시(하이픈)와 긴 밑줄(연장선)은 따로 검출한다.
- 합성 가사 줄(W2 렌더, 한글 OFL 폰트, 실제 악보식 간격)과 R-Dev-Tune으로 CER를 잰다. 부족하면 입력 준비(덩어리 경계, 여백, 확대 배율, 대비 정규화)를 개선한다. OCR 모델 미세조정은 CPU로 감당하기 어렵고 v1.1 원칙 밖이므로, 필요하면 수치와 함께 에스컬레이션한다(PLAN.md 7.4절 확장 규칙).
- 음절별 박스와 문자 확률을 낸다.

### T7.5 음절 분리와 절 배정

- 한글: 음절 블록 하나가 음절 하나다. 한 덩어리에 블록이 여럿이면 글리프 박스로 나눈다.
- 영어: 하이픈으로 syllabic을 정하고, 연장선이 있으면 extend를 표시한다.
- 절: 보표 아래 가사 줄의 세로 순서가 기본이다. 줄 앞의 "1.", "2." 표시가 있으면 그것을 우선한다. 가사가 여러 절이면 모든 절을 낸다.

### T7.6 기타 텍스트

- 제목: 첫 페이지 위쪽의 가장 큰 가운데 텍스트. 부제, 작곡·작사 표기(credit)
- 템포: 메트로놈 표기(음표 글리프 + "=" + 숫자)와 빠르기말(Moderato, 보통 빠르게 등)
- 섹션 라벨 사전: Verse, Chorus, Pre-Chorus, Bridge, Intro, Outro, Interlude, Tag, Ending, 전주, 간주, 후주, 1절, 2절, 후렴, 브릿지, 엔딩, 테두리 리허설 문자
- 진행 문구: D.S. al Coda, D.S. al Fine, D.C. al Fine, D.C. al Coda, To Coda, Fine, 코다로 등. 정규화된 값을 낸다.
- 사전은 **일반 음악 용어**만 담는다. 특정 곡의 가사나 제목을 사전에 넣지 않는다(헌장 F3).

### T7.7 `TextIR` 출력

CONTRACTS.md 3.6절. 모든 항목에 박스, 역할 확률, 텍스트, 대안, 신뢰도, 보표 연결을 담는다. 확률은 원시값으로 넘기고 최종 보정은 W8이 한다.

## 4. 첫 PR (착수 1주 목표)

PP-OCR 검출·인식 ONNX 기준선을 `src/clavis/text/`에 연결한다. W2 합성 페이지 100쪽에서 코드 줄과 가사 줄의 검출 재현율과 CER를 재는 스크립트를 만든다. 코드 문법 오토마톤 v0와 HarmonyMaker 어휘 적합성 테스트를 함께 낸다.

## 5. 수용 기준

| 지표 | G1 | G2 | G3 |
|---|---|---|---|
| 텍스트 검출 재현율 (코드·가사, SYN / R-Dev) | ≥ 95% / 보고 | ≥ 97% / ≥ 93% | 유지 |
| 역할 분류 정확도 (SYN / R-Dev) | ≥ 95% / 보고 | ≥ 98% / ≥ 95% | 유지 |
| 코드 문자열 정확 일치 (SYN ≥ 8 px / R-Dev) | ≥ 90% / 보고 | ≥ 97% / ≥ 92% | 유지 |
| 가사 음절 텍스트 정확 일치 (SYN ≥ 10 px, 한·영 각각 / R-Dev) | 보고 | ≥ 93% / 보고 | ≥ 95% / ≥ 90% |
| 텍스트 단계 지연 (REF-LAPTOP) | ≤ 8 s/쪽 | ≤ 4 s/쪽 | ≤ 4 s/쪽 |

## 6. 이 역할의 함정

- **특정 악보의 코드 폰트나 가사 배치에 맞춘 규칙**을 만들지 않는다(F12). 양식 차이는 합성 데이터의 폰트와 배치 다양성으로 흡수한다. 격차가 보이면 W2에 일반 용어로 보강을 요청한다.
- R-TGT 가사로 언어 사전이나 교정 사전을 만들지 않는다(F3, F8). 언어 사전은 공개 도메인 텍스트로만 만든다.
- 코드를 "화성적으로 그럴듯하게" 고치지 않는다. 문법 통과와 시각 확률만 쓴다. 조성 문맥을 이용한 교정은 v1 범위 밖이다.
- 역할 분류 오류는 조용히 퍼진다(예: 리허설 문자를 코드로 오인). 혼동 행렬을 항상 보고한다.
