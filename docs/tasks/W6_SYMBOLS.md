## 1. 미션

정규화된 보표 strip을 **기호와 그 관계**로 읽고, 그것을 LSTL lattice로 바꾼다. **GPU를 쓰지 않는다.** 모든 학습은 참조 노트북 CPU에서 모델당 4시간 안에 끝나야 한다.

너의 모델은 작다. 강함은 두 곳에서 나온다. 하나는 W2·W3가 만드는 **데이터의 다양성**이고, 다른 하나는 W8의 **전역 제약**이다. 그래서 네 가장 중요한 의무는 국소적으로 애매한 판단(beam이 1개인지 2개인지, 점이 있는지)을 **하나로 단정하지 않고 확률 후보로 넘기는 것**이다. 정답이 후보 안에 있으면 W8이 마디 길이로 골라낼 수 있다. 후보 밖에 있으면 아무도 복구할 수 없다.

음높이 계산과 마디 길이 맞추기는 네 일이 아니다(W8). 너는 보표 위치(pos)와 보이는 기호만 판단한다.

## 2. 범위

- 범위: S3a 후보 생성, S3b 분류·속성, S3c 관계, S3d 읽기 구성(`StaffLattice`), 무학습 템플릿 구성, 학습 조각 샘플러, CPU 학습 파이프라인, ONNX 런타임, 규칙 카탈로그(네 규칙), 모델 카드
- 범위 밖: strip 추출과 오선 검출(W5 소유. 너는 호출만 한다), 텍스트(W7), 음높이·마디·제약 해석(W8), 평가 지표(W4)

## 3. 작업 목록

### T6.0 CPU 학습 속도 측정 (첫 주)

- W1 배치 실행기로 소형 FCN(약 10만 파라미터, 48×48 조각)과 LightGBM의 REF-LAPTOP 학습 처리량(조각/초)과 RAM을 잰다. 스레드는 4, 8로 비교한다.
- 결과로 PLAN.md 7.5절의 시간 추정을 검증하는 보고서를 Orchestrator에게 보낸다. 4시간 상한 안에 들어갈 데이터 규모와 모델 크기를 제안한다.

### T6.1 무학습 템플릿 구성 (ADR-004의 기준)

- OFL SMuFL 폰트(Bravura, Leland, Petaluma 등)에서 음표 머리, 쉼표, 임시표, 음자리표, 숫자, 점, flag 글리프를 s*에 맞춰 렌더하고 흐림 변형을 만든다.
- strip(그리고 오선 제거 채널)에 정규화 상호상관을 적용해 후보를 낸다. stem과 barline은 세로선 검출기로 찾는다. 간단한 조립으로 lattice까지 만든다.
- 목적은 둘이다. (1) 학습 데이터가 오기 전에 끝까지 도는 경로를 만든다. (2) **학습이 얼마나 이득인지 재는 영구 기준**으로 남긴다. 학습 구성이 이 기준을 이기지 못하는 부분은 단순한 쪽을 쓴다.
- 이 구성의 규칙도 전부 카탈로그에 등록한다.

### T6.2 학습 조각 샘플러 (`training/models/symbols/sampler.py`)

- 흐름: W2 페이지 → **W3 페이지 단위 열화** → **W5 `extract_strip`**(검출 오차 모델만큼 흔든 기하 약 70% + W5 검출 결과 직접 사용 약 30%) → 조각
- 양성: 라벨 기호 앵커 중심(±작은 흔들림). 채널은 원본 + 오선 제거 2채널이다.
- 음성:
  - 무작위 배경
  - 앵커에서 0.3–1 staff-space 어긋난 위치
  - **혼동 유발 요소**: 가사와 코드 글자, 덧줄, 오선과 겹친 beam, stem, 이음줄 곡선, 페이지 가장자리
  - **어려운 음성 채굴**: 현재 모델이 SYN-Train에서 틀린 위치
- 균형: interline 구간, 렌더러, 폰트, 클래스별로 뽑는다. 시드로 결정적이다. 캐시는 uint8 배열, 합계 ≤ 2 GB.
- **금지**: R-LIED, R-TGT, R-LEGACY, Dev, sealed 이미지는 어떤 형태로도 넣지 않는다(헌장 F8).

### T6.3 후보 생성기 (S3a)

| 생성기 | 내용 |
|---|---|
| **G-FCN** | 소형 FCN 1–3개. 클래스별 heatmap을 낸다: 음표 머리(채움, 빈, 온, 슬래시, x), 쉼표(온·2분·4분·8분·16분·32분), 임시표 5종, 음자리표(G·F·C), 박자 숫자와 common/cut, 부점, 페르마타, segno/coda, 도돌이 점, 셋잇단 숫자. 수용 영역은 3–4 staff-space다. 조각 중심 가우시안 목표로 학습하고, 추론 때는 strip 전체에 합성곱으로 적용한다. 봉우리 추출과 NMS(반경은 staff-space, 레지스트리) |
| **G-CC** | 오선 제거 채널의 연결요소(정규화 크기에서 적응형 임계). 큰 기호 후보와, 거절해야 할 글자 침범 후보 |
| **G-VL** | 세로선 검출(열 방향 연속성). 높이, 두께, 보표 대비 위치를 쓰는 작은 분류기로 stem, barline, 기타를 구분한다 |
| **G-BM** | stem마다 끝부분 조각(약 2 × 4 staff-space)에서 beam 개수(0–4)와 flag 개수(0–4)의 확률을 낸다. 두꺼운 성분을 따라가 beam이 잇는 stem 묶음을 찾는다(기울기 허용) |
| **G-CV** | 오선 제거 채널의 가는 호 성분 + 분류기로 붙임줄·이음줄 후보와 양 끝점 |
| 덧줄 | 보표 위아래의 짧은 가로선. pos 판단 근거 |

- 모든 후보에 **출처(생성기)**를 기록한다. 생성기 합집합에 NMS를 적용하되, 점수가 낮은 후보도 버리지 말고 "누락 의심" 신호로 W8에 넘긴다.

### T6.4 분류와 속성 (S3b)

- **후보 분류기**: 48×48 조각(2채널) 입력의 작은 CNN. 거절 클래스를 포함한 클래스 top-k 확률을 낸다. 같은 특징으로 LightGBM 기준선을 만들고, 앙상블 여부는 ablation으로 정한다.
- **pos**: 음표 머리 중심의 세로 위치를 dewarp된 오선 행(strip 좌표에서 고정)과 비교해 연속값을 구한다. 잔차에 대한 가우시안(σ는 SYN에서 적합해 레지스트리에 둠)과 덧줄 근거로 이산 pos 확률을 낸다. 학습이 거의 필요 없다.
- **stem 방향과 붙는 쪽, 점 개수**(머리 오른쪽 1.5 staff-space 안의 칸 위치 탐색), **임시표 연결**(왼쪽 3 staff-space 안, 같은 pos ±1), **머리 종류 확률**
- 탐색 창은 모두 staff-space 단위이며 레지스트리 값이다.

### T6.5 관계와 `SymbolGraph` (S3c)

- 확률이 붙은 관계:
  - 머리–stem: 위로 향하면 머리 오른쪽 가장자리, 아래로 향하면 왼쪽 가장자리. 허용 오차는 staff-space 단위
  - 화음 소속(같은 stem의 머리들)
  - stem–beam/flag 개수
  - 점–머리, 임시표–머리
  - 붙임줄·이음줄 끝점–머리
  - 쉼표–성부, 덧줄–머리
- 규칙만으로 애매한 연결은 작은 LightGBM 관계 분류기가 판정하고, 상위 2개 대안을 남긴다.
- **성부 층**: stem 방향과 세로 배치로 2성부 구간의 성부 배정 후보를 만든다.
- 출력: `SymbolGraph`(CONTRACTS.md 3.5절)

### T6.6 읽기 구성기 → `StaffLattice` (S3d)

- x 위치로 열을 만든다. 성부 사이 같은 시점은 x 겹침(허용 오차는 staff-space)으로 맞춘다. 정렬은 W1 정규화기로 한다(CONTRACTS.md 4.2절).
- 음길이 = 머리 종류 + beam/flag 개수 + 점 + 셋잇단 숫자. 속성마다 분류기 분포에서 top-k 대안을 만든다.
- **N-best**: 가장 애매한 관계 조합에서 확률 곱이 큰 순서로 최대 8개 가설을 만든다. 열거 순서는 결정적이어야 한다.
- W1 문법 오토마톤을 통과하지 못하는 조합은 버린다.
- barline은 G-VL과 W5 barline을 합쳐 잠정 마디 경계를 만든다. 최종 마디 구조는 W8이 정한다.
- `spanU`는 기호 박스 그대로다. lattice 항목마다 **근거 기호 ID**를 붙인다. W8은 이것으로 evidence를 만든다.

### T6.7 CPU 학습 파이프라인

- PyTorch CPU 휠(스레드 ≤ 8), `torch.use_deterministic_algorithms(True)`, 시드 고정. W1 배치 실행기로 체크포인트와 재개를 지원한다. LightGBM 모델도 같은 실행기로 돌린다.
- **모델당 벽시계 ≤ 4시간, RAM ≤ 3 GB**(REF-LAPTOP). 넘으면 데이터나 모델을 줄이거나 ADR로 정당화한다.
- 모델 규모: FCN과 CNN은 각 ≤ 100만 파라미터(보통 5만–50만). 기호 모델 합계 ≤ 30 MB.
- 실험 레지스트리에 설정, 시드, 데이터 manifest digest, git SHA, **CPU 학습 시간**을 기록한다.
- 조기 종료와 체크포인트 선택은 SYN-Val-quick 규칙으로만 한다(헌장 F11).

### T6.8 런타임 (`src/clavis/symbols/`)

- ONNX Runtime CPU. FCN은 strip 전체에 한 번 적용한다(메모리가 넘칠 때만 겹침 타일).
- 선택: **test-time augmentation**. s*를 ±8% 바꿔 다시 돌리고 후보·속성의 일치도를 불확실성 신호로 W8에 넘긴다. 채택은 지연 대비 이득 ablation으로 정한다.
- 모델 파일은 `models/MANIFEST.json`에 등록한다.

### T6.9 평가와 보고

- SYN-Val(구간별): 클래스별 검출 재현율·정밀도, 속성 정확도(pos, beam·flag 개수, 점, 임시표, 머리 종류), 관계 정확도
- **읽기 IER**: lattice 1순위와 정답 LSTL의 항목 편집 거리 / 기준 항목 수
- **oracle@k**: 정답 속성값이 top-k 대안 안에 있는 비율. W8 제약 해석의 상한을 정하므로 가장 중요한 지표다.
- 무학습 구성 대비 학습 구성의 개선
- 파이프라인 단위: W8·W4를 거친 R-Dev K1, K2 기여. 인식에 영향을 주는 PR은 헌장 5절의 전체 비교 보고서를 첨부한다.
- 실패 사례는 **이미지가 아니라 패턴 단위**로 목록을 만든다(예: "오선과 겹친 2중 beam, interline ≤ 9 px").

### T6.10 규칙 카탈로그 (`configs/symbols/rules.yaml`)

S3a–S3d에서 손으로 쓴 규칙마다 ID, 조판 관례로 쓴 설명, 단위(staff-space), 출처(convention 또는 fit), on/off 플래그, ablation 기여도를 등록한다(헌장 4.2절). 게이트마다 규칙 수와 기여도 표를 보고한다.

## 6. 이 역할의 함정

- **규칙 증식**: 검출–조립 구조는 규칙을 부른다. 새 규칙을 넣고 싶을 때마다 먼저 물어라. 이것은 분류기 학습 데이터(어려운 음성, 혼동 요소)로 풀 수 있는가? 규칙이 꼭 필요하면 조판 관례로 설명할 수 있어야 하고, 카탈로그에 등록하고, 합성 패턴 계열로 검증한다(헌장 5절).
- **한 장에 맞춘 탐색 창**: "이 사진에서는 점이 머리에서 1.7 sp 떨어져 있다" 같은 관찰로 창을 조정하지 않는다. 창은 SYN 분포와 Dev-Tune 전체의 sweep으로 정한다.
- **조기 단정**: 분류기 확률을 argmax 하나로 잘라 넘기면 W8이 고칠 여지가 사라진다. oracle@k가 떨어지는 변경은 1순위 정확도가 올라도 기각 후보다.
- **학습–추론 불일치**: 학습 조각을 추론과 다른 코드로 만들면 실사에서 무너진다. 반드시 W5 함수와 같은 정규화를 거친다.
- **이진화 의존**: 오선 제거 채널은 보조다. 판단은 그레이스케일 원본 채널을 함께 봐야 한다. 초기 전역 이진화는 Audiveris가 실패한 지점이다.
- **체크포인트 쇼핑**: Dev-Check로 모델을 고르지 않는다.
