## 1. 미션

깨끗한 렌더를 **실제 사용 경로를 거친 이미지**로 바꾸는 라이브러리를 만든다. 실제 경로는 휴대폰 촬영, 메신저 재압축, 저해상도 스캔, 화면 캡처다. 핵심은 두 가지다. (1) **목표 interline로의 해상도 저하**를 정밀하게 제어한다. (2) 모든 기하 라벨을 정확히 따라 변환한다. 이 라이브러리가 "저해상도 일반화"의 주 무기다.

## 2. 범위

- 범위: 열화 연산 라이브러리, 촬영 경로 프리셋, 라벨 변환, 사실성 평가, 성능
- 범위 밖: 렌더링(W2), strip 추출(W5), 실사 데이터 수집(W4, Custodian)

## 3. 작업 목록

### T3.1 라이브러리 구조

- 연산은 `(image, labels, rng, params) → (image, labels, applied_params)` 형태의 순수 함수다. 라벨은 점, 박스, polyline, 마스크를 지원한다.
- 파이프라인은 연산을 조합하고, 매개변수 분포를 설정(YAML)으로 정의한다. 샘플한 매개변수를 모두 기록해 재현할 수 있어야 한다.
- 난수는 `numpy.random.Generator` 하나를 시드로 받아 쓴다. 같은 시드면 같은 결과다.
- 입력은 페이지 단위(2–8 MP)이고 그레이스케일과 컬러를 모두 지원한다.

### T3.2 연산 계열 (최소 8계열)

| 계열 | 연산 |
|---|---|
| 기하 | 회전(±8°), 원근(homography, 촬영 각도 0–35°), 원통형 종이 휨, 약한 메시 왜곡, 여백 잘림, 배경(책상·천 텍스처) 합성 |
| 조명 | 선형·방사형 그라데이션, 그림자 도형(손, 휴대폰 그림자), 비네팅, 반사광(glare) |
| 광학 | 초점 흐림(원판 커널), 가우시안 흐림, 모션 흐림(손떨림) |
| **해상도** | 목표 interline로 축소한다. 축소율 = 목표 interline ÷ 렌더 interline. 보간 방식(area, bilinear, bicubic, nearest)을 무작위로 고르고, 선택적으로 다시 확대한다(메신저·뷰어 동작 모사) |
| 압축 | JPEG(품질 25–95, 크로마 서브샘플링, 1–3회 반복), WebP |
| 센서·잡음 | 가우시안, 포아송, 소금·후추, 색 잡음, 노출 부족 |
| 스캔 | 이진화(전역, 적응형), 디더링, 복사기 열화(굵어짐, 끊김), 비침, 기울어진 급지 |
| 종이·표식 | 종이 질감, 얼룩, 형광펜, 연필 표시, 스테이플, 구김 |
| 화면 | 모아레, 화면 픽셀 격자, 화면 반사 |

- 텍스처는 **자체 촬영하거나 CC0인 것만** 쓴다. 출처를 등록부(W2 `REGISTER.md`)에 올린다.

### T3.3 촬영 경로 프리셋 (ADR-011)

`scan-150`, `scan-300`, `scan-bw`, `phone-daylight`, `phone-indoor`, `phone-angle`, `phone-shadow`, `phone-curl`, `messenger-kakao`(축소 + 강한 JPEG), `screenshot-downscaled`, `photocopy`, `screen-photo`.

- **목표 interline 분포**(학습 기본값): 7–10 px 40%, 10–14 px 35%, 14–24 px 20%, 24 px 이상 5%. 설정으로 조절한다.
- 프리셋마다 매개변수 범위와 근거를 문서화한다.

### T3.4 라벨 변환 정확성

- 기하 연산은 라벨을 같은 변환으로 옮긴다. 폴리라인 점, 박스(네 모서리 변환 → 외접 사각형), 마스크(같은 warp)가 대상이다.
- 해상도 변경 뒤의 **실제 interline 값**을 라벨 메타데이터에 기록한다.
- 검증: 격자·점 패턴 합성 이미지로 라벨 오차 ≤ 0.5 px(출력 해상도 기준)를 확인한다. hypothesis로 무작위 매개변수 속성 시험을 한다.

### T3.5 사실성 평가

- **통계 비교**: R-Dev-Tune 실사와 합성의 분포를 비교한다(KS 통계, 분위수). 비교 대상은 interline, interline으로 정규화한 흐림 지표(Laplacian 분산), JPEG 품질 추정(양자화표), 잡음 수준, 배경 불균일, 대비다.
- **도메인 분류기 시험**: 실사와 합성의 strip crop을 구분하는 작은 분류기의 AUC를 보고한다. 낮을수록 사실적이다. 게이트 필수 기준은 아니지만 매 게이트에 보고한다.
- 조정은 **분포 수준**에서만 한다(헌장 A5). 실사 이미지의 픽셀, 배경, 텍스처를 복사하지 않는다(F8). W4에게서 받는 것은 집계 통계뿐이다.

### T3.6 성능

- 목표: 2–4 MP 페이지 기준 코어당 초당 5쪽 이상(일반 프리셋). OpenCV 벡터 연산을 쓰고 파이썬 루프를 피한다.
- 학습 데이터로더에서 즉석 적용할 수 있어야 한다. 무거운 연산(원통 휨 등)은 미리 계산한 맵을 캐시한다.

### T3.7 (선택) 경로 보정 키트 — Custodian 협조

- Custodian이 기준 이미지 몇 장을 카카오톡 등으로 보냈다가 받고, 원본과 결과 쌍을 준다. 이 쌍으로 축소 규칙과 JPEG 양자화표를 추정해 `messenger-*` 프리셋을 보정한다.
- 기준 이미지는 자체 제작 패턴(격자, 합성 악보)만 쓴다. 악보 내용은 필요 없다.

### T3.8 변환 불변성 시험 지원 (W4와 협업)

헌장 6절의 입력 변환 8종(스케일, 회전, 여백, JPEG 재인코딩, 밝기, 감마, 가장자리 자르기)을 이 라이브러리의 결정적 함수로 제공한다. W4의 `eval/metamorphic/`이 이를 호출한다.

## 4. 첫 PR (착수 48시간 목표)

기하(회전, 원근), 해상도(목표 interline 축소), JPEG 세 연산과 라벨 변환, 격자 패턴 정확성 시험. 렌더 한 장으로 interline 16, 12, 10, 8, 7 px 열화본을 만든 시연 스크립트를 함께 낸다.

## 5. 수용 기준 요약

- G1: 연산 8계열 이상, 프리셋 전체, 사실성 보고서 v1, 성능 목표 충족
- G2: 사실성 보고서 v2(Dev-Tune 통계 반영), 경로 보정(선택)

## 6. 이 역할의 함정

- **실사 이미지 한 장 흉내 내기 금지.** "이 JPEG과 똑같이 보이게"가 아니라 "실사 분포를 덮게"가 목표다.
- 열화가 **라벨을 거짓으로 만드는 경우**를 막는다. 예를 들어 강한 잘림이 보표를 자르면, 그 보표의 LSTL 라벨은 무효다. 이런 샘플은 라벨에 `truncated`를 표시하거나 버린다.
- 해상도 저하의 결과를 "인간도 읽을 수 없는 수준"까지 만들 수 있다. interline 6 px 미만 샘플은 `illegible` 후보로 표시해 학습 손실과 평가를 분리한다.
