## 1. 미션

**일반화의 원천**을 만든다. 실제 찬양 리드시트와 인쇄 악보의 다양성을 넉넉히 덮는 합성 데이터를 권리가 깨끗한 상태로, 정확한 라벨과 함께 대량 생산한다. 목표는 실사 이미지가 "학습 때 본 변형 중 하나"처럼 보이게 하는 것이다.

## 2. 범위

- 범위: 라이선스 등록부, 기호 코퍼스 수집·정규화, 절차적 리드시트 생성기(LeadGen), 렌더링 팜, 라벨 추출, shard 패키징, SYN-Val 고정, R-PC 인쇄 묶음 생성 지원
- 범위 밖: 열화(W3), 모델 학습(W5–W7), 평가 지표(W4)

## 3. 작업 목록

### T2.1 라이선스 등록부

- `training/data/licenses/REGISTER.md`와 기계 판독용 `sources.json`. 원천마다 이름, URL, 버전, 라이선스, 허용 용도(train, eval, 가중치 배포), 표기 문구, 확인 날짜, 확인 방법을 적는다.
- 초기 후보:
  - PDMX: Zenodo 배포본의 `no_license_conflict` 하위집합 중 Public Domain Mark와 CC0만. 항목별 라이선스 필드로 거른다.
  - Mutopia: 곡별로 확인한다. CC-BY-SA는 Orchestrator 승인이 있어야 쓴다.
  - LeadGen 자체 생성물
  - OpenScore Lieder: **평가 전용, 학습 금지**(헌장 7절). 등록만 해 둔다.
- 가사 텍스트:
  - 한국어: 한국 저작권법상 보호기간이 끝난 작가의 원문만 쓴다(1962년 이전 사망 작가. 작가별로 사망 연도를 확인해 기록한다).
  - 영어: 미국 기준 공개 도메인 텍스트(1929년 이전 출판 찬송가 가사 등)
  - 자체 작성 문장
- 폰트: SMuFL 음악 폰트(Bravura, Petaluma, Leland, Leipzig, Gootville, Sebastian 등)와 텍스트 폰트(Noto Sans/Serif KR, 나눔 계열, Gowun, IBM Plex Sans KR, Pretendard, 재즈풍 텍스트 폰트 등). 라이선스(OFL 등)를 하나씩 확인해 기록한다.
- 수용 기준: 학습 shard의 모든 항목이 등록된 원천을 참조한다(CI 검사). 등록되지 않은 원천은 0건이다.

### T2.2 코퍼스 수집·정규화

- 원천을 내려받고 라이선스로 거른다. MusicXML을 파싱해 LSTL v0.1 지원 범위 밖 요소가 있는 곡은 제외하거나, 의미에 영향이 없는 요소만 제거한다. 무엇을 제거했는지 기록한다.
- 곡을 분류한다: 리드시트형(단일 보표 + 가사나 코드), 성악, 피아노, SATB.
- W4의 멜로디 지문 도구로 중복을 제거하고 곡 단위 분할 ID를 붙인다. **평가 전용 곡 풀 지문과 겹치는 곡은 자동 제외한다.**
- 산출물: `data/corpus/<source>/<id>.musicxml` + `data/manifests/train/corpus-*.json`
- 수용 기준: 필터 후 학습용 곡 ≥ 20,000(목표). 조, 박자, 음길이, 기보 특성 분포 보고서.

### T2.3 LeadGen — 절차적 리드시트 생성기

설정(YAML)으로 분포를 조절하고, 시드가 같으면 같은 MusicXML이 나오는 생성기를 만든다.

- **조·박자**: 찬양에 흔한 조(C, D, E, F, G, A, B♭, E♭, A♭, D♭와 단조)에 가중치를 주되 ±7 전부를 포함한다. 4/4, 3/4, 6/8, 2/4, 12/8, 2/2. 곡 중간 박자·조 변경 약 5%.
- **형식**: 4·8마디 프레이즈, 못갖춘마디(약 30%), 도돌이, 볼타, D.S./D.C./Coda/Segno/Fine(약 20%), 섹션 라벨(Verse/Chorus/Bridge/Intro/Outro와 1절, 2절, 후렴, 간주, 브릿지, 전주, 후주, 엔딩)
- **선율**: 순차 진행 위주의 랜덤 워크와 도약. 음역은 성부별(소프라노, 알토, 테너 8vb, 베이스)
- **리듬**: 당김음(점8분+16분, 8–4–8), 박과 마디를 넘는 붙임줄, 16분음표, 셋잇단(약 5%), 쉼표, 꾸밈음(약 2%), 페르마타, 여러 마디 쉼표, **리듬 슬래시 마디**(약 10%의 곡), **2성부 구간**(약 10%)
- **코드**: 온음계 진행, 부속 화음, 차용 화음, 슬래시 코드, sus, add, 7th, 9th, 변화음. CONTRACTS.md 6절 문법의 전체 어휘와 일부 어휘 밖 코드(`C5` 등). 마디당 밀도 0–4.
- **가사**: 1–4절. 한국어는 음절 블록 단위, 영어는 하이픈 음절 분리, 멜리스마와 연장선.
- **머리글**: 제목, 부제, 작곡·작사 표기 자리. 가짜 이름이나 공개 도메인 이름을 쓴다.
- **시드 네임스페이스**: 학습용은 `train-*`만 쓴다. `eval-*` 네임스페이스는 W4가 평가 전용 곡 풀을 만들 때만 쓴다.
- 수용 기준: 8코어에서 1만 곡을 1시간 안에 생성한다. 파싱과 마디 유효성 100%. P0 기보 요소(PLAN.md 3절)별 출현 빈도표에서 모든 요소가 1% 이상.

### T2.4 렌더링 팜

- 렌더러 어댑터(외부 프로세스, 비배포):
  - **Verovio**: 폰트 Leipzig, Bravura, Gootville, Leland, Petaluma. 페이지 크기, scale, 간격, 줄바꿈, 가사 크기를 무작위화
  - **MuseScore 4 CLI**: `.mss` 스타일 무작위화(음악 폰트, 텍스트 폰트, spatium, 여백, 가사 폰트와 크기, 코드 표기 스타일 standard/jazz, 보표 간격, 시스템당 마디 수). Linux 헤드리스 실행 방법을 문서화한다.
  - (선택) LilyPond
- 추가 무작위화: 한 시스템당 마디 수 2–6, 보표 크기, 머리글·꼬리글·페이지 번호·저작권 줄, 리허설 마크, 제목 글꼴
- 출력: **SVG(압축) + 라벨 + 렌더 메타데이터**(렌더러, 버전, 옵션, 폰트)를 저장한다. 래스터(렌더 interline 24–32 px)는 필요할 때 SVG에서 만들고, 래스터 캐시는 상한을 둔다. REF-LAPTOP의 여유 디스크가 약 10 GB이기 때문이다.
- **저장소 데이터 총량 ≤ 4 GB**(코퍼스 + SVG + 라벨 + 캐시). 넘을 것 같으면 외장 저장소로 옮기고 보고한다.
- 렌더링은 CPU 작업이다. W1 배치 실행기의 야간 큐로 돌리고, 중단돼도 이어서 렌더한다. 처리량(쪽/시간)을 측정해 보고한다. 선택적으로 무료 클라우드 CPU 노트북을 보조로 쓸 수 있다(사적 데이터 금지, 필수 경로 아님).
- 실패는 건너뛰고 원인별로 센다.
- 수용 기준: 렌더러 2개 이상, 음악 폰트 4개 이상, 텍스트 폰트 10개 이상(한글 4개 이상). 1,000쪽 시험 생산.

### T2.5 라벨 추출

SVG, 원본 MusicXML, 렌더 메타데이터로 페이지마다 다음을 만든다.

- 오선 polyline, 시스템·보표 소속, 마디 박스, barline 위치와 스타일
- **보표별 시각 LSTL**(CONTRACTS.md 4.2절: 시스템 첫머리 재인쇄, courtesy 기호 포함)과 열마다의 x 앵커
- **기호 박스와 관계 라벨**(CONTRACTS.md 3.5절 클래스): 머리–stem, stem별 beam·flag 개수, 점–머리, 임시표–머리, 붙임줄·이음줄 끝점, 같은 stem의 화음, 성부. **W6 분류기 학습의 핵심 라벨**이므로 정확도를 감사 이미지로 검증한다.
- 텍스트 박스와 역할(코드, 가사 n절, 제목, 템포, 섹션, 진행 문구, 기타), 문자열, 가사 음절별 박스, 코드의 인쇄형과 정규형
- **교차 검증**: LSTL과 원본 MusicXML의 논리 내용이 같은지 확인한다(W8 이론 모듈이 나오면 그것으로, 그 전에는 자체 검사기로). notehead 수와 음표 수, 박스가 페이지 안에 있는지, 가사 음절 수와 부착 음표 수도 확인한다.
- 수용 기준: 1,000쪽에서 검증 오류 0(제외한 항목은 사유 기록). 무작위 50쪽을 겹쳐 그린 감사 이미지 보고서(라벨 어긋남 0).

### T2.6 데이터셋 패키징

- 페이지 단위 shard(ADR-009: WebDataset tar 또는 Parquet): SVG, 라벨 JSON, 메타데이터
- 학습 조각은 **페이지에서 즉석 생성**한다. 경로는 W3 열화 → W5 strip 추출 함수(공용) → W6 조각 샘플러다. strip이나 조각을 따로 대량 저장하지 않는다.
- **SYN-Val**: 500쪽을 렌더러, 폰트, 기보 특성으로 층화해 고정한다. 열화본은 W3 프리셋과 고정 시드로 interline 구간(6, 7, 8, 9, 10, 12, 14, 16, 20, 24 px)별로 **결정적으로 재생성**한다. 저장하는 것은 SVG, 라벨, 시드·매개변수 manifest뿐이다. 부분집합 SYN-Val-nightly(100쪽)와 SYN-Val-quick(30쪽 × 6구간)도 함께 고정한다(EVALUATION.md 2절). manifest digest로 동결해 W4에 넘긴다.
- 데이터셋 카드: 원천 비율, 분포, 알려진 편향
- 수용 기준: G1까지 렌더 ≥ 5,000쪽과 SYN-Val 동결. G2까지 렌더 ≥ 20,000쪽(보표 약 15만 개). 모두 저장소 데이터 총량 ≤ 4 GB 안에서.

### T2.7 R-PC 인쇄 묶음 지원 (W4와 협업)

W4가 준 평가 전용 곡 목록을 렌더러와 폰트를 섞어 인쇄용 PDF로 만든다. 식별 코드는 넣지 않는다. 렌더 원본(PNG, SVG, MusicXML)을 함께 W4에 넘긴다.

## 6. 이 역할의 함정

- **평가 곡의 학습 유입**: 지문 필터를 우회하는 경로(수작업 추가, 다른 이름의 같은 곡)를 만들지 않는다.
- **좁은 분포**: 기본값이 "깨끗한 Verovio 한 가지 모양"으로 수렴하지 않게 한다. 렌더러와 폰트별 비율을 매 보고서에 싣는다.
- **라벨 어긋남**: 렌더러 버전이 바뀌면 SVG 구조가 바뀐다. 렌더러 버전을 고정하고 감사 이미지로 검증한다.
- **스타일 격차 보강의 한계**: Dev-Tune에서 드러난 양식 격차(예: 굵은 산세리프 코드, 위첨자 확장음)를 생성기에 넣는 것은 허용된다(헌장 A5). 그러나 **특정 악보를 흉내 낸 템플릿**은 금지다. 격차는 일반 용어로 기술하고, 여러 변형으로 넣고, 전후 비교로 증명한다.
- 사적 이미지(R-TGT, R-LEGACY)는 볼 권한도 없고 필요도 없다. 스타일 격차 정보는 W4의 집계 보고서로만 받는다.
